# Connect4 Space 寬螢幕空間利用增量設計

日期：2026-08-30  
狀態：待書面核准

## 背景

目前 Space 的 `.gradio-container` 最大寬度固定為 `1240px`。在約
`1920px` 的寬螢幕上，應用程式只使用畫面左側約三分之二，右側留下大片
無效空白；棋盤圖片也未填滿棋盤欄位。手機版則已具備清楚的單欄排列，
不需要重新設計。

## 目標

- 提高寬螢幕的有效利用率，同時維持聚焦、易讀的對弈介面。
- 讓棋盤圖片充分使用棋盤欄位，不再出現明顯的欄內空白。
- 保留至少 `20px` 的主要文字、低圓角與簡單操作方式。
- 不破壞手機單欄版面，也不產生水平捲動。

## 非目標

- 不新增遊戲功能、控制項、動畫或資訊面板。
- 不修改模型、MCTS、事件輸入輸出或遊戲流程。
- 不採用無限制滿版；超寬螢幕仍需保留受控邊界，避免閱讀與操作距離過大。

## 版面設計

### 容器

- 桌面最大寬度由 `1240px` 調整為 `1660px`。
- 容器以 `margin-inline: auto` 置中，左右 padding 使用受控的響應式數值。
- 在 `1920px` viewport，主要容器應使用至少約 80% 的可用寬度，但不得超過
  `1660px`。

### 棋盤與控制區

- `900px` 以上維持雙欄，棋盤區與控制區使用 `62:38` 的目標比例。
- 棋盤圖片應在不變形的前提下填滿棋盤欄位的可用寬度；不得裁切棋盤或欄號。
- 控制區保持足以容納兩個棋色選項與三個難度選項的寬度，不讓單一控制項
  無意義地拉長。
- 兩欄頂端對齊；棋盤下方欄位按鈕繼續與棋盤寬度對齊。

### 響應式規則

- `900px` 以下保持既有單欄順序：標題、棋盤、欄位按鈕、狀態與控制區。
- 390px 手機仍須維持 7 個落子按鈕同列，且所有主要文字至少 `20px`。
- 1024px、1440px 與 1920px 均不得出現水平溢出。

## 實作邊界

- 修改集中在 `space/app.py` 的 `APP_CSS`。
- 不新增 JavaScript，也不改 Gradio 元件樹或公開 API endpoints。
- 延續現有 CSS token、色彩、直角面板與按鈕小圓角。

## 驗證

1. 先新增會因現有 `1240px` 上限與棋盤未填滿而失敗的 UI contract test。
2. 最小修改 CSS 使測試通過，並確認完整 pytest suite 維持綠燈。
3. 在 390、1024、1440、1920px viewport 檢查：
   - 主要文字最小 `20px`；
   - 無水平溢出；
   - 1920px 容器寬度至少為 viewport 的 80%；
   - 桌面棋盤圖片寬度至少為棋盤面板寬度的 90%，且不變形、不裁切；
   - AI 思考期間棋盤仍保持可見。
4. 推送前執行套件相容性、部署 bundle 乾跑與 GitHub CI。
5. CI 通過後才更新 Hugging Face Space，並在正式站重跑功能與視覺煙霧測試。

## 發布判準

只有本機測試、響應式瀏覽器測試、GitHub CI 與正式 Space 煙霧測試全部通過，
才可判定發布完成。任何一關失敗都暫停後續部署並先修正根因。
